# B站视频分析总结

> 把一期 B站视频（连同评论区）变成一份**可核对的深度分析报告**——单文件 HTML + 同源 PDF。
> 一个给 AI Agent 用的 Skill：装上它，你的 Agent 就知道怎么"读透"一期视频，而不是复述它。

---

## 这是什么 / 不是什么

| | 是什么 | 在哪 | 谁维护 |
|---|---|---|---|
| **本项目** | 一个 **Agent Skill**（`SKILL.md` 规范）：给 Agent 读的规则集 + 取数脚本 + 报告模板 | 装进 Agent 的 **skills 目录** | 本仓库（GitHub） |
| **上游 MCP** | `@xzxzzx/bilibili-mcp@1.14.1`，**第三方**的 MCP 服务器 | 跑在 npm 缓存里，npx 启动 | 第三方作者 |
| **本仓库的补丁** | 一套**可逆补丁**，修上游 MCP 已知的 3 个 bug | `assets/mcp-patch/` | 本项目 |

**一句话**：**skill 是给 Agent 读的规则，MCP 是它可以调用的外部服务，补丁是让这个外部服务少犯错的工具链。**

- 你装的是 **skill**（一个文件夹），**不是**一个 MCP server——别往 MCP 配置里填这个仓库的路径
- **MCP 是可选增强**（字幕、关键词定位、章节、收藏夹），不装也能用
- 本仓库**不包含** MCP 的代码，只有它的补丁

## 它解决什么问题

让 AI "总结一下这个视频"，你得到的大多是一份复述——把视频里的话换种说法再讲一遍，真假难辨、无法核对、看完还是不知道该信多少。

这个 skill 换了一套做法：**把视频当作"一个待审查的信息源"来对待**。

它产出的报告回答的是这些问题：

- 这个视频**属于哪一类**、最核心的主张是什么、**说得对不对**、值不值得信？（一屏定性卡）
- 它的逻辑链条是「绪论 → 本论 → 结论」的哪几段？**链条在哪里断掉**？
- 评论区有**哪几类观点**？各自占多少份量——不是一堆平铺摘录，而是带分布的聚类
- 哪些说法**被评论区当场修正/推翻**了？
- AI 字幕有没有**误转**（数字、术语、人名），哪些地方**说话人归属都可能搞错**？
- 所有数字、论断，能不能**一键跳回原片核对**？

一句话：**它不复述视频，它审查视频。**

## 产出的报告长什么样

固定七大部分，**顺序不可乱**（「关键参数」与「内容纠偏」刻意后置为速查层）：

```
报头 + 定性卡（一屏判断：类型 / 主题 / 核心主张 / 说得对不对 / 价值评估）

01 视频概览与定性      数据侧写 → 主题与隐含前提 → 逐项判定表 → 分人群价值
02 视频核心总结        绪论 → 本论（逻辑链/机制拆解）→ 结论 → 链条断在哪
03 评论区概览与总结     结构侧写 → 观点谱（N 簇 × 三轴分布图）→ 反常发现
04 评论区核心总结       逐簇「绪论/本论/结论」+ 与视频逐条对照
05 关键参数与对照时间点  ← 速查层
06 内容纠偏            ← 速查层（AI 字幕误转清单 / 说话人归属 / 视频自身不自洽）
07 延伸发散            补充 → 更深一层 → 发散联想
```

几个刻在流程里的设计：

- **三源区分**：每一条判断都标注「视频说 / 评论说 / 我推断」，不允许出现没有来源的裸判断
- **观点三轴**：观点簇按「普遍度（多少人提到）/ 认同度（多少人点赞）/ 争议度（多少人回复去争）」三个轴上各自归一化——**不合成分数**（三者不可通约，加权求和是伪精度）
- **时间戳全部是可点链接**：`[09:41](url?t=581)`，一秒跳回原片核对
- **零 emoji、不含任何读者个人信息**——报告设计上就可直接对外分享
- **模板化排版**：样式表固定，AI 只写正文片段，版式不漂移，也省输出 token

HTML 与 PDF 内容完全一致（PDF 由同一份 HTML 渲染，折叠区自动展开），中文可抽取、超链接保留。

## 八型视频分流

同一套骨架，不同类型的视频**细节呈现不相同**——这个判断不靠模型临场发挥，而是写死的：

| 代号 | 类型 | 一句话识别 |
|---|---|---|
| A | 技术 · 工具 · 部署 | 有参数要照抄、有性能要复核、有坑要避 |
| B | 深度访谈 · 对谈 | 多人说话，观点容易安错人头 |
| C | 财经 · 市场 · 投资 | 有行情/报价/预测，口径五花八门 |
| D | 商业 · 公司分析 | 拆解某个产品或公司的成败 |
| E | 政经 · 政策 · 宏观 | 政策、产业、地缘，事实与判断混杂 |
| F | 科普 · 健康 · 教育 | 给操作建议，与身体/生活直接相关 |
| G | 方法论 · 教程 | 教你怎么做事，价值在可迁移 |
| H | 娱乐 · 亚文化 · 段子 | 情绪型内容，视频没信息量——**重心全在评论区** |

每个类型有自己的：定性卡字段、各章呈现形式、图表类型、后置取舍。详见 `references/video-types.md`。

## 这个 skill 里沉淀了什么

除了流程本身，仓库里最有价值的部分是**经过实战验证的"踩坑知识"**——每一条都附了验证方式：

- **上游 MCP 包的三个真实 bug** 及其补丁：412 风控（WBI 签名）、评论 `pn` 参数被废弃导致结果成倍重复、评论条数上限过窄
- **AI 字幕的误转模式**：同音词整体替换（把「长上下文」转成「常识」）、数字失真、**没有说话人分离**（访谈类最容易把观点安错人头）——以及"反向核实"：术语不规范**不等于**转写错误，受访者本人可能就这么说
- **话题取样偏差**：热度排序奖励"短、狠、可表态"，惩罚"长、细、需要条件"——**热度用来选样本，内容密度用来排序**
- **评论区图片不是表情包**：2026-10-19 发现接口一直在返回 `content.pictures`，而两条通道的归一化都把它丢了。实测缇宝那期 57 条带图、占样本赞量 96.8%，最高赞 21,065 是一张梗图；刹车那期 637 赞的评论配的是四车型刹车踏板结构对比图。判据用**图片占样本赞量**（≥15% 必做），读图分两级：联系表选片、原图判读
- **赞／币比**：投币是 B站唯一有成本的认可动作——赞/币 ≥ 20:1 基本可判定为情绪型内容，重心应转到评论区
- **排版陷阱**：打印时 A4 折算宽约 605px，不带 `screen` 限定的窄屏 media query 会让 PDF 变成移动端布局（屏幕上看不出）
- **B站反爬与截断**：缺 `Referer` 直接 567（yt-dlp 同样）；大文件单次请求会被**静默截断**，而截断的 m4s 仍能被 ffprobe 读出完整时长，到解码才报错——报错位置离病因很远。`fetch_media.py` 把这三坎封在内部
- **抽帧密度不是越密越好**：固定 1 fps 只是厂商默认值（1 小时 ≈ 93 万 token）；主流实现的有效帧数落在 300–800。**按事件分配预算，不按秒**——幻灯片 0.2–0.3 fps 就够，软件演示才需要 1 fps
- **抽帧的两种目的**：补全（口播有指代、零数字）与**核对（口播给了数字、但口径可能对不上）**。只按"信息缺口"判会漏掉全部核对型发现，而硬伤往往就出在"口播听起来完整"的地方
- **成本单位是图片，不是字数**：一次整页图读取 ≈ 三四千字文本。所以先跑脚本筛、再看联系表、最后只回读 3–5 张——这条让一篇 18 分钟的报告里有约 7 分钟被省掉
- 以上的完整清单与验证记录，都在 `references/troubleshooting.md`、`references/lessons.md` 与 `references/CHANGELOG.md` 里

## 常见问题

**Q：怎么更新到新版本？**
在 skill 目录里 `git pull`（zip 用户重新下载覆盖）。如果还配了 MCP 通道，顺手重跑一次
`scripts/check_setup.py`，确认补丁和登录态都还在。

**Q：改了仓库里的文件，客户端却没生效？**
（这是**维护者**场景：你的 skill 目录不是项目仓库本身。）改了真源要送过去：

```bash
cd <项目仓库目录>
python scripts/sync_skill.py --check     # 看漂移
python scripts/sync_skill.py --deploy    # 同步
```

同步后重启/重连一次客户端，让它重新加载 skill。**别从 GitHub 反向拉**——那会回滚掉你还没推送的本地改动。
如果你的 skill 目录是用 junction / 符号链接直连项目目录的，就**没有这个问题**，改完立刻生效。

**Q：一定要装 MCP 吗？**
不。`scripts/fetch_video.py` 是自包含的取数主力（仅标准库）：元数据 + 评论 + **评论图片及其统计**都能拿，无需登录。装了 MCP 多出的是：字幕扫码登录更省事、关键词定位、章节、收藏夹。

注意**评论默认不走 MCP**——它在归一化时只保留 `content.message`，会把评论图片、表情、用户等级、IP 属地全部丢掉（1.14.1 与 1.14.3 实测都一样）。而"图片占赞"这个判据只有 `fetch_video.py` 算得出来，用 MCP 取评论会导致整片评论区图像静默漏掉。详见 `SKILL.md`「三条数据通道」。

**Q：PDF 生成失败？**
PDF 依赖 Playwright（可选安装）。未安装时报告只出 HTML，装了自动出 PDF，详见 `INSTALL.md`。

**Q：视频没有字幕（或 AI 字幕质量太差）怎么办？**
走「无字幕固定链路」，三步都已有脚本，不需要现场拼代码：

```bash
python scripts/fetch_media.py BVxxxxxxxx --audio --out ./m    # ① 音轨（12 MB / 0.6 s）
python <本地 ASR>/transcribe.py m/audio.m4s --model large-v3 --language zh --formats srt
python scripts/fetch_media.py BVxxxxxxxx --video 1080 --out ./m   # ③ 要读画面数字才下（46 MB / 3 s）
```

推荐 faster-whisper（有 GPU 时实测 17–30 倍实时），转写结果直接替代字幕进入分析流程。**要读表格里的数字就必须下 1080p**（360p 的文字不可读）。完整做法见 [`references/troubleshooting.md`](references/troubleshooting.md) §6.5，密度与时机见 [`references/video-sampling.md`](references/video-sampling.md)。

**Q：为什么不干脆把视频每一帧都抽出来给模型看？**
因为成本不在抽帧，在**读图**。固定 1 fps 处理 1 小时视频约 93 万 token；一次整页图读取 ≈ 三四千字文本。本仓库的做法是先在本地把帧压成结构（去重 + 按口播分段 + 联系表），只把「每段首帧 + 变化点」交给模型——通常 15–25 张就够。详见 `references/video-sampling.md` 与 `references/lessons.md`。

**Q：读不到某个视频的字幕 / 报错？**
付费、会员、地区限制、私密内容读不到是正常结果，skill 不尝试绕过。其余问题先跑 `scripts/check_setup.py`，再查 `references/troubleshooting.md` 的症状表。
