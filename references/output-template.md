# 报告骨架 + 命名与落盘规范

> 本文件定义**报告长什么样**（有哪些部分、什么顺序）。
> **每个 class 怎么写**看 `references/report-authoring.md`；**不同类型怎么调**看 `references/video-types.md`。

---

## 一、命名与落盘（硬性）

**文件名 = 文档 `h1` 标题 = `YYYYMMDD-《视频标题》分析总结`**（HTML 与 PDF 同名，扩展名不同）

```
20261016-《视频标题》分析总结.html
20261016-《视频标题》分析总结.pdf
```

| 项 | 规定 |
|---|---|
| 日期 | 取**分析当天**，不是视频发布日期；`YYYYMMDD` 无分隔符 |
| 《》内 | **照录视频原始标题**，不改写、不缩写、不加译者注 |
| 多 P 视频 | 标题后追加 `-P{n}` |
| 非法字符 | 标题含 `/ \ : * ? " < > \|` 时替换为全角，**只换字符不动文字** |
| 超长标题 | 超过约 60 字可截断到第一个副标题分隔符，末尾**不加**省略号 |
| 落盘位置 | **写之前必须问用户一次**；未回复 / 说"随便"→ 落**桌面**。用户已在请求里指定位置时直接用（落盘前回显一次） |
| 回显 | 拿到路径后**回显一次**再写 |

> 这一问最好在**开始取数时**就发出去，别等数据拉完再等回复。

## 二、骨架

**骨架固定，任何视频类型都不许改。** 变的是每一块里装什么、用什么形式装（见 `video-types.md`）。

```
<header class="masthead">            报头
    kicker / h1 / standfirst / meta
<section class="bleed"> + .verdict   定性卡 —— 一屏判断，读者 10 秒决定要不要往下读

01 视频概览与定性
   1.1 这是哪一类视频（数据侧写：币赞比、评论结构…）
   1.2 主题与核心主张（以及它的隐含前提）
   1.3 说得对不对（逐项判定表）
   1.4 价值评估（分人群给结论）

02 视频核心总结
   2.1 绪论：它立了什么靶子 / 要回答什么
   2.2 本论：逻辑链条（或机制拆解 / 操作流程 —— 按类型）
   2.3 结论：最终主张
   2.4 链条断在哪几处

03 评论区概览与总结
   3.1 评论结构侧写（总量 / 取样 / 热度分布 / 取样偏差声明）
   3.2 观点谱：N 个簇 × 三个轴（普遍度 / 认同度 / 争议度）+ 小倍数图
   3.3 反常发现（热度样本漏掉了什么）

04 评论区核心总结
   4.1–4.N 逐簇展开：每簇「绪论 → 本论 → 结论」+ 与视频逐条对照
   （簇顺序按内容密度排，不按数据大小排）

05 关键参数与对照时间点        ← 后置速查层
06 内容纠偏                    ← 后置速查层
   6.1 字幕来源与可靠性
   6.2 误转清单（只列会导致理解错误的）
   6.3 视频自身的不自洽
   6.4 纠偏结论

07 延伸发散                    ← 最后
   7.1–7.N 补充 / 更深一层 / 发散联想
   7.last 「还没解决的 / 可以继续挖」+ 「要不要接到你自己身上」勾子

<footer>  一句话最终建议 · 数据源 · 「本报告不含任何读者个人信息，可自由分享」
```

**顺序红线**：
- 「关键参数」与「内容纠偏」**必须后置**——它们是速查层，不是阅读主线
- 「延伸发散」在最后
- 无内容的部分可**整节省略**，但不许并入其他部分、不许提前

## 三、三源区分（每一条判断都要标）

| 标记 | class | 含义 |
|---|---|---|
| 视频说 | `.src-v` | 照录视频内容，配时间戳 |
| 评论说 | `.src-c` | 引号 + 作者 + 点赞数 |
| 我推断 | `.src-m` | 你自己推出来的，**绝不能写成"视频说的"** |

**不允许出现没有标记的裸判断。**

---

## 四、内容层面的硬规则

1. **结论前置**：每个部分第一句就是判断，细节放后面。
2. **时间戳必须是链接**：`<a class="ts" href="…?t=秒数">09:41</a>`，秒数取整。
3. **不当复述机**：如果某一节只是把视频讲了一遍，删掉或压成一句话。
4. **不贴全字幕**，除非用户明确要求。
5. **找不到就写找不到**："这条我没有核实"比含糊过去好。
6. **误转清单只列会导致理解错误的**——AI 能自行还原的用词偏差、冗余字不列（或折叠在「已排除」里）。
7. **报告不含读者个人信息**——报告要能对外分享。个性化落到最后一部分的勾子。
8. **全文零 emoji**——包括引用里的 👍 ✅ ❌，一律换文字。

## 五、产出与自检

```bash
python scripts/render_report.py --body body.html \
    --title "20261016-《视频标题》分析总结" \
    --out "<目录>/20261016-《视频标题》分析总结.html" --pdf
```

- 脚本会报：HTML 大小、style 块数、PDF 页数 / 链接数 / 耗时
- **style 块数必须为 1**，否则说明片段里混进了 `<style>`
- **版式问题只能靠眼睛**：翻一遍 PDF，找大面积空白页、被切断的内容、错位的图表

完整自检清单见 `references/report-authoring.md` 第五节。
